# NetExplorer — criação do projeto em Go

Crie um novo projeto chamado **NetExplorer**, escrito em **Go**, destinado à descoberta, inventário, identificação e exploração de serviços disponíveis em uma **rede local própria ou autorizada**.

O projeto deve ser desenvolvido como uma base de código sustentável e extensível, não como um script descartável.

Antes de implementar, analise o problema, valide a arquitetura proposta, apresente a árvore inicial de arquivos e somente depois comece a criação dos arquivos.

---

## 1. Objetivo

O NetExplorer deverá descobrir dispositivos existentes na LAN e correlacionar informações provenientes de múltiplas fontes, tais como:

- SSDP/UPnP;
- DLNA;
- mDNS/DNS-SD;
- ARP/neighbor table;
- Nmap;
- posteriormente SMB;
- posteriormente NFS;
- posteriormente WebDAV.

O sistema deverá tentar responder perguntas como:

- Quais dispositivos existem na rede?
- Qual IP e MAC pertencem a cada dispositivo?
- Qual hostname é anunciado?
- Qual fabricante/modelo foi identificado?
- O dispositivo é TV, NAS, computador, roteador, MediaServer, MediaRenderer etc.?
- Quais serviços ele anuncia?
- Existem bibliotecas de vídeos, imagens ou músicas disponíveis?
- Existem compartilhamentos públicos explicitamente disponibilizados?
- Quais ações são compatíveis com o dispositivo?

O sistema **não deverá**:

- tentar senhas;
- realizar brute force;
- explorar vulnerabilidades;
- contornar autenticação;
- tentar acessar compartilhamentos privados;
- executar scanners agressivos por padrão.

```bash

```

```bash

```

antes de habilitar integração.

Não permita que esse comando elimine ou substitua o `AGENTS.md`.

Depois de verificar o dry-run, faça somente as alterações de projeto necessárias.

Não executar configuração global RTK automaticamente.

Não modificar:

```text
~/.codex/config.toml
~/.config/rtk/config.toml
```

sem autorização explícita.

### Uma alteração importante em relação ao prompt anterior

Eu colocaria o **RTK como parte do ambiente de desenvolvimento, e não dentro do NetExplorer**. A versão atual do RTK suporta especificamente Codex com `rtk init --codex`; para agentes sem integração automática, ele também possui modos de awareness e proxy, além de `rtk gain` para acompanhar a redução de tokens. [GitHub](https://github.com/rtk-ai/rtk/blob/develop/docs/guide/getting-started/configuration.md?utm_source=chatgpt.com)

Também é importante a verificação com `rtk gain`, porque há mais de um projeto chamado `rtk`; a documentação oficial recomenda essa checagem para confirmar que está instalado o **Rust Token Killer `rtk-ai/rtk`**. [GitHub](https://github.com/rtk-ai/rtk/blob/develop/docs/guide/getting-started/installation.md?utm_source=chatgpt.com)

Com isso, eu considero o prompt significativamente melhor preparado para o Codex: ele define **produto, arquitetura, limites, segurança, documentação, RTK, testes e critérios de conclusão**, mas ainda mantém o desenvolvimento dividido em fases para evitar o Codex tentar construir tudo de uma vez.
